# 智慧物流与配送模拟系统

## Lab01

### 功能要求

**1.**创建并显示包裹

​	（1）能够根据输入创建包裹，并显示单个包裹的完整信息。包裹信息至少包括<u>编号、寄件人、收件人、重量和当前状态</u>。

​	（2）能够连续创建不少于3个包裹， 并以列表形式显示当前全部包裹。新包裹的状态统一为**“待入站”**

**2.**查询包裹

​	（1）能够根据包裹编号查看指定包裹，并能够查看全部包裹。

​	（2）查询不存在的编号时应给出提示，不得显示其他包裹的信息。

**3.**基础数据校验

​	（1）包裹编号不能为空且不能重复，重量必须大于0，寄件人和收件人不能为空。

​	（2）输入不符合要求时应拒绝创建，并明确说明失败原因。



## Lab02

### 功能要求

**1.**更新配送状态

​	（1）包裹能够按照“待入站—已入站—运输中—已签收”的顺序更新状态。

​	（2）状态更新成功后应显示包裹的最新状态。

**2.**限制非法状态变化

​	（1）跳过中间状态、倒退状态或再次更新已签收包裹时，应拒绝操作。

​	（2）拒绝时应显示当前状态和允许的下一状态，包裹原状态保持不变。

**3.**计算基础运费

​	（1）能够根据包裹重量计算并显示基础运费 ，本次统一采用
$$
5元基础费 +  2元 \times 重量
$$
公式。

​	（2）费用查询不改变包裹状态，相同包裹重复计算应得到相同结果。

**4.**增量开发要求

​	（1）在同一工程中保留并复验**Lab01**已经完成的功能，不能将本次作业写成独立程序。

​	（2）新增功能应在现有工程和已有数据基础上继续扩展，不得形成互不关联的两套程序。

​	（3）提交**Lab01**到**Lab02**的变更说明，写清修改位置、原因、影响范围和回归测试结果。

## Lab03

### 功能要求

**1.** 创建并显示站点

​	（1）能够将创建物流站点，站点信息至少包括编号、名称和当前包裹数量。

​	（2）能够显示单个站点信息以及当前全部站点。

**2.**办理包裹入站和移出

​	（1）能够将符合条件的包裹加入指定站点，入站成功后包裹状态变为“*已入站*”。

​	（2）能够将包裹移出站点并进入下一配送状态；同一包裹不能重复入站。

**3.**查询站点包裹

​	（1）能够显示指定站点当前管理的全部包裹，并按编号查看其中一个包裹。

​	（2）入站或移出后，站点显示的包裹数量必须与包裹列表一致。

**4.**增量开发要求

​	（1）在同一工程中保留并复验<u> Lab01</u> 至<u>Lab02</u>已经完成的功能，不能将本次作业写成独立程序。

​	（2）新增功能应在现有工程和已有数据基础上继续扩展，不得形成互不关联的两套程序。

​	（3）提交<u>Lab02</u> 到<u> Lab03</u>的变更说明，写清修改位置、原因、影响范围和回归测试结果。
